## 编号规则

- 编号 `ADR-<NNN>` 三位递增，**延续 DD-1.x 已占用的 001~003**，新决策自 **ADR-004** 起；
- 文件名：`ADR-<NNN>-<kebab-slug>.md`（如 `ADR-004-vectorstore-pgvector.md`），本目录内唯一；
- 正文结构（与 DD-1.2~1.4 口径一致）：**背景 → 结论 → 理由 → 被否方案 → 影响**；
- 一条 ADR 只记一个决策；修订只能改"状态"与追加"后续记录"，结论被替换时新写一条并将旧条
  置为 `Superseded by ADR-xxx`（禁止原地改写结论，历史决策必须可追溯）。

## 状态枚举与签署

`草案 Draft` → `提议 Proposed` → `已采纳 Accepted` → `已签署 Signed`（架构委签署，关联 Q/任务号）
→ `已废弃 Deprecated` / `已被取代 Superseded`。
**签署人姓名为会议决议产物，仅由架构委在签署版填入；模板与本清单不预填任何姓名。**

## 模板（复制起步）

```markdown
# ADR-NNN：<决策标题>

- 状态：Proposed
- 日期：YYYY-MM-DD
- 决策者/评审：<角色，签署时填>
- 关联：DD-x.y / PRD-x.y / 评审问题 <C-x/H-x/...> / Open Question <Qn>（若有）/ 任务 <IT-x.xx>

## 背景
<什么问题、什么约束下必须做决策；引用数据/用例，不写结论性形容词>

## 结论
<一句话可执行的决策，含被选方案的关键参数>

## 理由
<为什么选它；可复算的量化依据优先（成本/延迟/一致性）>

## 被否方案
<列出否决的备选与否决理由；后续复议时在此追加链接>

## 影响
<对架构/契约/数据/流程/计划的连锁修改点，逐条列；需回写哪些文档（DD-15 依赖结论、附录 F 状态列等）>
```
